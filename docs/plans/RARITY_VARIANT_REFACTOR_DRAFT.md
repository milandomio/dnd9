# 稀有度变体改造草案

## 状态

未决定执行。保留当前 Cloudflare Pages `404.html` 接管方案；本草案不改变现有路由、静态产物或客户端逻辑。

## 背景

当前品质变体使用完整路径，例如 `/zh-Hans/lootdrops/Spear_1001/`。静态 HTML 已裁剪时，由 Cloudflare Pages 的根 `404.html` 启动 SPA，客户端仍按路径请求 `Spear_1001.json`。

可选替代方向是始终使用默认品质的静态页面作为承载页，将实际品质放入查询参数，例如：

`/zh-Hans/lootdrops/Spear_5001/?r=1001`

其中 `Spear_5001` 是唯一静态详情壳，`r=1001` 指示客户端加载 `Spear_1001.json`。

## 潜在收益

- 所有品质 URL 都命中默认品质静态页并返回 HTTP 200，不依赖 `404.html` 接管。
- 不再生成非默认品质的静态 HTML，文件预算保持低位。
- 稀有度切换仅变更查询参数，详情 JSON 仍按实际品质独立加载。

## 暂不执行原因

- 查询参数会污染当前纯路径 URL 风格，并与站内其他详情链接不一致。
- 变体 URL、canonical、分享链接和语言切换的最终语义尚未确定。
- 现有 404 接管已满足在线直达需求；在没有明确 URL 设计前不应扩大客户端路由改造范围。

## 若决定执行

1. 确定查询参数名称、默认品质省略规则和旧变体路径的处理策略。
2. 调整 `VariantSwitch` 生成的链接与当前品质判定。
3. 调整 `LootdropDetailPage`：从 `r` 解析实际品质，并以该品质构造版本化详情 JSON 请求。
4. 保留语言切换、预加载、canonical、Sitemap 和 PWA 深链行为的一致性。
5. 在 Cloudflare Pages 实测默认品质页、查询变体页、无效参数和无 JavaScript 响应。
