# 游戏内地图识别优化

## 目标

在已完成的本地截图识图功能上降低完整截图识别耗时，并允许用户按截图质量调整识别召回率。所有处理继续在浏览器本地完成，不上传截图，不改变 SSG、SEO 和静态部署架构。

## 当前基线

- 初版对每张完整截图执行“页面模板数 × 4 个旋转 × 8 个尺度”的全屏模板匹配。
- `/zh-Hans/lootdrops/GoldenKey/` 使用 `test-cap.png`（废墟 2 层/地穴）时，11 个模板识别到 5 个模块，耗时约 51 秒。
- `test-cap1.png` 的 `TreasureRoom_01` 裁剪图旋转 `0/90/180/270°` 均识别成功，单次约 0.7 秒。

## 已完成优化

1. [x] 自动定位高亮的大地图面板 ROI，将精匹配范围从完整 `800x450` 工作图缩小到约 `330x320`。
2. [x] 将 ROI 内坐标偏移映射回原始截图，导出仍保持 `1920x1080`。
3. [x] 根据 ROI 占截图比例和匹配模块尺寸识别 `5x5/7x7` 网格；证据不足时不猜测。
4. [x] 已知网格只检查相邻 3 个模板尺度；无法判断网格或裁剪图继续使用完整尺度列表。
5. [x] ORB 场景特征只计算一次，所有未命中模板共享描述子。
6. [x] 模板超过 18 张时先在半尺寸 ROI 粗筛，再对最高 18 个候选做精匹配。
7. [x] 增加地图分组选择器；选项实时来自当前页面经过现有过滤后仍显示的地图分组，默认选择“全部”，失效选项自动回退“全部”。

## 精度参数设计

| 预设 | 初始阈值 | 目标 |
|------|----------|------|
| 标准 | `0.52` | 优先抑制误报，保持当前行为 |
| 高召回 | `0.45` | 识别压缩、遮挡和轻微尺寸误差 |
| 极高召回 | `0.38` | 尽量找全目标，允许更多误报 |
| 自定义 | 用户输入 | 用于特定截图、UI 缩放和后续校准 |

阈值越低，识别成功率和误报率都会上升。结果仍经过局部峰值筛选、同模板非极大值抑制和跨模板重叠去重，不直接绘制所有低分候选。

## 精度校准结果

GoldChest 页面选择 `Inferno` 分组并粘贴 `test-cap-dy.png`：

| 预设 | 阈值 | 识别数 | 对 5 个已知目标的结论 |
|------|------|--------|-----------------------|
| 标准 | `0.52` | 2 | 误报风险低，召回不足 |
| 高召回 | `0.45` | 4 | 适合一般压缩截图，仍漏 1 个 |
| 极高召回 | `0.38` | 5 | 当前样图达到 5/5 |
| 自定义 | `0.32` | 6 | 至少出现 1 个疑似误报 |

GoldChest 的分组选择器默认“全部”，选项实时来自当前页面可见地图卡片；实测包含 GoblinCave、FireDeep、IceCavern、IceAbyss、Ruins、Crypt、Inferno、ShipGraveyard。切换到 Inferno 后模板从 40 张缩减到 5 张。

`test-cap1.png` 在标准 `0.52` 下旋转 `0/90/180/270°` 仍全部识别到 1 个模块。7x7 截图在降低工作分辨率后需要高召回档：OldRustyKey 页面高召回识别 2 个、极高召回识别 3 个，网格分类始终为 7x7。

## 当前架构

```text
当前页面可见地图卡片
  -> 按 image URL 去重并携带 DungeonModule.group
  -> 用户选择全部或具体地图分组
  -> 开启识图后动态加载 OpenCV.js 和对应 WebP
  -> 粘贴截图并缩放到最长边 600px
  -> 亮度密度定位大地图 ROI
  -> ROI 比例推断 5x5/7x7 并选择相邻尺度
  -> 模板超过 18 张时执行半尺寸粗筛
  -> 0/90/180/270° 多尺度模板精匹配
  -> 未命中模板共享场景 ORB + RANSAC 兜底
  -> NMS 去重、回写 ROI 偏移和原图比例
  -> 50% 绿色蒙版预览与 PNG 导出
```

识图状态由 `MapImageRecognition.tsx` 管理，算法集中在 `mapImageRecognition.ts`。页面只负责提供当前过滤后会渲染的模板和地图分组，不包含 OpenCV 逻辑。

## 最终验收标准

- GoldChest + Inferno + `test-cap-dy.png`：极高召回必须命中 5 个已知真值，且误报为 0。
- OldRustyKey + `test-cap-7x7.png`：网格必须为 7x7；完成真值后按真实目标数量验收。
- GoldenKey + `test-cap.png`：网格必须为 5x5，已确认目标不能低于初版 5 个。
- `test-cap1.png` 四个方向必须全部命中同一 TreasureRoom 模块。
- 选择地图分组后只请求和识别该组模板；默认选择全部，当前分组消失时自动回退全部。
- 自定义阈值限制在 `0.20-0.90`；手动输入不触发 OpenCV 或模板重新加载。
- 选定分组后的 1920x1080 完整截图目标耗时不超过 10 秒，识别期间页面可交互。
- 截图无上传请求；SSG、SEO、PWA 安装与静态部署行为保持不变。
- Prettier、TypeScript、ESLint、i18n、quick SSG、HTTP 200 和 Playwright 全部通过。

## 风险与约束

- 降低阈值会同时增加召回和误报，不能用“识别数量等于真值数量”替代边界级真值验证。
- 600px 工作图会损失 7x7 细线特征；后续可按网格自适应分辨率，但必须配合 Worker 控制耗时。
- OpenCV.js 动态 chunk 约 15.5 MB，不进入 Workbox 安装预缓存；首次开启仍需要下载。
- 多个模块共享相似纹理，ORB 和模板匹配都可能在门廊、墙体等重复结构上误配，必须保留几何校验和 NMS。
- 地图 UI 比例、语言、显示器缩放和截图压缩可能影响 ROI 阈值，需要用更多真实截图验证后再扩大自动推断范围。

## 暂停点

状态：**暂停，等待用户明确说“继续执行”**。

恢复后按以下顺序执行：

1. 从 P1 开始，先增加识别结果明细和调试 JSON，不直接继续降低阈值。
2. 为炼狱 5 个目标建立边界真值，确认极高召回的 5 个结果确实对应 `1-3/1-5/2-4/3-3/3-4`。
3. 再进入 P2 Worker 和模板缓存，将选定分组完整图耗时降到 10 秒以内。
4. P1/P2 验收后才实现 P3 自动分组建议。
