# 网站美化计划方案

**状态**：待执行（仅方案，未改前端代码）
**目标**：在保留 React、Ant Design、SSG、多语言和现有页面信息架构的前提下，以最小改动提升 DarkFlashNav 的统一性与游戏资料站观感。

## 约束

- 不替换 Ant Design，不引入新的 UI 框架或 Tailwind。
- 不改变路由、数据请求、SSR 数据结构或页面功能。
- `App.tsx` 与 `ssr.tsx` 的 Provider 结构及 Ant Design 主题配置必须同步，避免 hydration 不一致。
- 现有浅色/深色切换必须保留，所有新增视觉变量均由 `useTheme.tsx` 提供。
- 每个阶段独立提交，可单独回退；每阶段完成后再进行下一阶段。

## 当前问题

- `useTheme.tsx` 的背景、surface、card 均为中性灰，缺少游戏资料站的视觉识别。
- Ant Design 的主色仍为默认蓝色，与站内青色 accent 不一致。
- 页面大量内联样式虽已共享主题 token，但圆角、阴影、描边和 hover 强度不完全统一。
- 首页卡片混用高饱和边框、渐变、发光 Emoji 与大幅缩放，信息密度高但视觉焦点分散。
- 导航栏将面包屑和首页呈现为大面积描边按钮，削弱搜索功能的主次关系。

## 分阶段实施

### P1：统一设计 token

**改动文件**：

- `web/src/hooks/useTheme.tsx`
- `web/src/App.tsx`
- `web/src/ssr.tsx`

**实施内容**：

- 深色主题由纯灰调整为低饱和墨黑、岩灰表面和暗金强调色；浅色主题使用暖白、浅砂岩灰和相同强调色。
- 保留 `bg`、`surface`、`card`、`text`、`muted`、`border`、`accent` 等既有 token 名称，避免扩大组件改动面。
- 补充需要的状态 token，例如弱强调背景或悬停边框，仅在确有重复使用时新增。
- 在两处 `ConfigProvider` 同步配置 `colorPrimary`、背景、边框、圆角和控件高度，使 Input、Select、Spin 与自定义区域一致。

**验收**：

- 深浅主题下文字、边框和输入框对比度可读。
- SSR 页面与客户端首屏没有 hydration 警告。
- 不修改任何页面数据或交互。

### P2：导航与全局微调

**改动文件**：

- `web/src/components/NavBar.tsx`
- 可选新增 `web/src/styles.css`，并在客户端与 SSR 共用入口引入

**实施内容**：

- 将导航容器改为更轻的顶部工具栏，降低边框和背景存在感。
- 搜索框作为唯一主控件；语言、主题和返回首页降为次级控件。
- 面包屑从描边按钮改为文字链接或低对比度标签，保留当前路径与点击行为。
- 若新增全局样式，仅放置字体栈、焦点态、链接、滚动条和移动端布局等跨组件规则，不迁移现有页面逻辑。

**验收**：

- 桌面与窄屏下搜索、语言和主题开关可访问且不溢出。
- 搜索结果下拉层仍高于页面地图和卡片。

### P3：首页卡片收敛

**改动文件**：

- `web/src/pages/HomePage.tsx`

**实施内容**：

- 保留现有四列网格、数据、链接和页面类型颜色映射。
- 类型色从整张卡片的粗边框改为小面积侧边、图标底板或标题标记。
- 降低卡片渐变、阴影和 hover 位移强度；移除 `scale()`，避免卡片相互挤压。
- Emoji 可保留为临时占位；如后续有统一图标素材，再单独替换，避免本阶段引入素材工作。

**验收**：

- 首页仍显示全部入口和数量，链接路径不变。
- 鼠标和键盘焦点均能清楚辨识卡片。
- 1200px 以下网格按现有响应式规则或新增全局断点正常收缩。

### P4：列表与详情页视觉一致性

**改动文件**：

- `web/src/pages/ListPage.tsx`
- `web/src/pages/DetailPage.tsx`
- `web/src/pages/LootdropDetailPage.tsx`
- 视实际重复情况调整相关公共组件

**实施内容**：

- 统一列表卡片、详情区块、统计区、地图面板外框的圆角、边框和标题层级。
- 保持详情页、掉落页与地图渲染的数据条件完全不变，只调整呈现样式。
- 优先抽取重复且稳定的样式常量；不为单一页面新增抽象组件。

**验收**：

- items、monsters、props 三种共用详情页与 lootdrop 独立详情页的风格一致。
- 地图坐标、调试面板、爆率和多语言文本不受影响。

## 建议执行顺序

1. 先完成 P1 并提交，作为全站色彩基线。
2. 在浏览器确认深浅主题和首页后执行 P2、P3。
3. P4 仅在前三阶段方向确认后进行，避免全站样式返工。

## 验证与提交

每个阶段完成后执行：

```bash
cd web
npm run format
npm run format:check
npx tsc --noEmit
```

在 `dev` 分支使用 Vite HMR 于 `http://localhost:8090/` 检查；无需为纯视觉改动重跑数据管道或 SSG。提交时仅 stage 本阶段涉及文件及 `docs/SESSION_CHANGES.md`，不混入其他进程的 WIP。

## 不在本计划内

- 更换 UI 框架。
- 重写为 Tailwind、CSS Modules 或 CSS-in-JS。
- 修改 API、JSON、数据库、路由与 i18n key。
- 制作或引入一套新的插画、图标、字体授权素材。
